# Page heads — design direction

**Status:** Proposal. The CSS is built and three pages are converted as exemplars.
Nothing else is touched until Adam has looked at it.

Adam, 2026-08-10: *"a total re-invigoration of all those with what makes sense …
use your best judgement for redesign."*

---

## 1. What the audit actually found

Measured across 73 pages at 1280px:

| | |
|---|---|
| Distinct hero implementations | **27** |
| Pages using the shared `.page-hero` | **6** |
| Pages whose page-head has no `<h1>` at all | **32** |
| Generated by `usmcmin-build` — off limits to hand-editing | **13** (`.fc-header`) |
| Genuine one-offs available to convert | **46** |
| Height spread | 76px to 900px+ |

Twenty-seven implementations of one component is the whole problem in a single
number. It isn't that any individual page-head is ugly — `about.html` is good —
it's that nothing is shared, so every new page re-decides margin, type scale,
whether there's a kicker, whether there's an `<h1>`, and how much room the fixed
masthead needs. That is what reads as amateur: not one bad screen, but the
absence of a system across many adequate ones.

## 2. The decision: promote, don't invent

The instinct with a brief like "re-invigorate" is a new look. That would be the
wrong call here, for two reasons.

1. **The good pattern already exists.** `about.html` — kicker, serif `h1`, one
   lede line, centred, calm — is exactly the brand as `CLAUDE.md` describes it:
   muted, static, scannable, no hype. It is used on 6 of 73 pages.
2. **A new look would need 46 page conversions before anyone could judge it.**
   Promoting the existing pattern lets each page be converted independently and
   look right immediately.

So: **`.page-hero` becomes the system.** It gains the parts the one-offs were
each reinventing, and the one-offs get deleted as they convert.

What is genuinely new is small and deliberate:

- **A rule under the kicker.** A 48px hairline in `--gold`. It reads as a
  ribbon device rather than decoration, and it gives every page-head the same
  optical anchor. This is the one flourish; it earns its place by replacing the
  ad-hoc dividers several pages had invented separately.
- **An optional shield mark** above the kicker, at 44px, for section landing
  pages only. Not on every page — if the shield is everywhere it stops meaning
  anything.
- **A defined type scale** rather than each page choosing a `clamp()`.
- **Three sizes**, because a scorecard table page and the Mission page should
  not have the same page-head. `--compact` (utility pages, ~150px),
  default (~260px), `--feature` (section landings, ~340px).

## 3. The system

```html
<header class="page-hero">                      <!-- or .page-hero--compact / --feature -->
  <img class="page-hero-mark" src="…">          <!-- optional, feature only -->
  <p class="page-hero-eyebrow">About</p>
  <h1>The Man Behind the Ministry</h1>
  <p class="page-hero-lede">One sentence. Two at most.</p>
  <div class="page-hero-actions">…</div>        <!-- optional -->
</header>
```

Rules that are enforced by the CSS rather than left to each page:

- Top padding is `var(--nav-clear)` plus the size's own breathing room, so a
  page-head can never sit under the masthead again.
- The lede is capped at `62ch`. Long measure is the most common way a calm
  layout starts to look careless.
- `h1` uses one scale: `clamp(1.9rem, 1.2rem + 2.4vw, 3.1rem)`.
- The eyebrow is `--gold`, uppercase, `.18em` tracking — the existing kicker,
  fixed in one place.
- Actions get `min-height: 48px`, so page-head CTAs stop being the undersized
  tap targets the mobile audit kept finding.

## 4. Every page-head gets an `<h1>`

32 pages currently have none. That is not a style question — it is the single
biggest heading signal for search and the first landmark a screen-reader user
jumps to. Converting a page to `.page-hero` forces the question, because the
markup has an `h1` slot in it.

Where the visible design genuinely shouldn't carry a headline, the `h1` goes in
visually-hidden but present. `.sr-only` is already in the sheet.

## 5. Graphics — deliberately not yet

Adam asked for updated graphics via ChatGPT. I have not generated any, on
purpose: art direction before art. Once the layout is approved, the shield mark
slot and the `--feature` size define exactly what's needed — a small set of
section marks at one size, one style, on transparent ground. Generating images
first would mean commissioning art to fit a layout nobody has agreed to.

The `/rebrand-graphic` skill already covers driving ChatGPT and compositing the
real ministry shield, so that pipeline exists when the direction is settled.

## 6. Rollout, if approved

| Wave | Scope | Why this order |
|---|---|---|
| 1 | The 3 exemplars in this PR | Proves the system on a utility page, a content page, and a landing page |
| 2 | ~20 RESOLUTE pages (`sc-`, `sh-`, `st-`, `mp-`, `cmp-` containers) | Nearly identical one-offs; highest consistency win per edit |
| 3 | Remaining hand-authored one-offs | Individually judged |
| 4 | `.fc-header` (13 pages) | **Requires a change in `usmcmin-build`, not here** — never hand-edit the generated HTML |

Each wave re-runs `scripts/audit-header-overlap.js` and
`scripts/audit-mobile-polish.js`, which must stay at zero.

## 7. Open question for Adam

The shield mark on `--feature` page-heads: yes on section landings only, or not
at all? My recommendation is section landings only — roughly six pages. Putting
it on every page-head is how a mark stops carrying weight.

## 9. Rollout attempt 1 — what went wrong (2026-08-10)

Wave 2 was attempted and **reverted before shipping**. Worth recording so it is
not retried the same way.

The RESOLUTE cluster (`state`, `stats`, `map`, `compare`, `how-to-use`,
`find-my-reps`) all share the shape
`div.<x>-container > div.<x>-hero > span.<x>-hero-badge + h1 + p`, so adding
`page-hero-eyebrow` to the badge span looked like a one-line conversion.

Two things broke it:

1. **Each page's own badge rule still won.** Those styles live in the page's
   inline `<style>`, which comes after the external sheet, so the eyebrow's
   font-size and tracking were overridden. Computed sizes stayed at 10.56px and
   11.2px instead of the system's 12.16px — the pages ended up *differently*
   inconsistent, which is worse than leaving them alone.
2. **The badge is a pill, the eyebrow is not.** `.page-hero-eyebrow::after`
   draws a 48px rule beneath the label. Applied to a pill-shaped badge it drew a
   horizontal line *inside* the pill, which reads as a rendering bug.

**The lesson:** this component cannot be adopted by adding a class. A page
converts by replacing its head markup and deleting its own head rules, or it
does not convert. Half-adoption is a regression.

So wave 2 should be done **one page at a time, with a render check on each**,
not as a bulk class sweep. Budget accordingly — six pages is an afternoon, not
a script.
